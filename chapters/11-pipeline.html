11.2实拍口播为主时：泳道换一下

片型管线配置
教学/科普/产品宣传（图形驱动）调研/定位（人＋agent）→ 视频脚本（G2/G3 人审）→ 三条并行泳道：HyperFrames 做 MG·图解·数据·章节卡，AI 视频模型 做少量实拍感镜头（带参考锚点），TTS 出口播（词级时间戳）→ 同步/组装（字幕·混音）→ 门禁人审 → 渲染/分发（可经剪映草稿收尾）
真人出镜/访谈/课程录像（实拍驱动）① ChatCut 做粗剪与口播清理（去口癖、压停顿）→ ② HyperFrames 做 MG 包装（标题、数据卡、章节卡）→ ③ 导出可编辑剪映草稿，人工做最后一公里的审美收尾
💡 为什么这样分工 每个工具都被放在它最强的工序上：实拍素材的叙事性剪辑是代码路线最弱、ChatCut 最强的区域；MG/图解/数据是 HyperFrames 的主场且可批量复用；AI 生像素只出现在「拍不到又需要实拍感」的少数镜头（第 9 章的成本结论在这里落地）。

11.3动手环节：30 分钟最小流水线

  1. 挑课题：挑一个已有调研结果的课题——调研报告、定稿文章、笔记都行，它就是脚本的唯一内容来源。
  2. 写定位（10 分钟，过 G1）：受众、前 15 秒钩子、目标时长。
  3. 起草脚本（过 G2）：让 agent 从调研结果起草视频脚本，先只写分段口播，自己朗读一遍再定稿。
  4. TTS 拿真实时长：出音频，拿到真实时长——这一步先于任何画面。
  5. 补画面栏（过 G3）：在同一份脚本里补每镜画面，必填「素材来源」字段。
  6. 只做一镜：用代码 MG 做一张数据动画或章节卡，渲染出来看效果。入口：HyperFrames 官方仓库的 README 有最小示例，照抄改字就是第一镜。
  7. 沉淀设计契约：把配色、字体、卡片样式写成一份设计契约文件——下条视频直接复用。
💡 压轴直觉：先有一条能看的，再有一条满意的 用最小流程跑通端到端验证选题，再投入搭建完整 agent 流水线——避免在没人看的选题上建完美工程。工程是放大器，选题才是信号源。

11.5边界提醒：能帮你什么，不能证明什么

✅ 本系列能帮你❌ 本系列不能证明
用三轴、景别、风格、知识域拆解任何一条视频看懂了就做得出——拆解能力要靠练习积累，不是读完就有
建立音频先行、分镜独立、闸门到位的工作流保证第一条视频就「满意」——审美判断无法代劳
按成本与修改成本选每镜素材来源AI 视频跨镜一致性已解决——关键帧图再图生视频仍是绕行方案，结论保质期约 6–12 个月
理解剪映 / ChatCut / HyperFrames 的分工「HyperFrames 对 agent 更友好」有独立背书——这是基于公开信息的判断，尚无公开基准测试，应视为待验证的假说
⚠️ 时效性提醒 剪映价格、字幕准确率、各工具集成的模型清单均随版本变化——动手前以官方当季信息为准，别把任何一张对比表当成长期依据。
✓ 全站小结 看懂：视频是「来源 × 职能 × 图层」的叠加；景别有含义，风格写进契约。
生产：脚本从调研结果长出来，口播与画面同档分管；音频先行，四个闸门：定位、口播栏、画面栏、终审。
工具：剪映、ChatCut、HyperFrames 是三个物种，按工序混着用，不是二选一。

把流程写成代码，把判断留给自己。
